How savings are calculated

The formula

savings = tokens_saved × list input price per token

Headroom counts every token it removed from a request before it went to the model (compression only — cache discounts are tracked separately and never mixed into this number). Each saved token is priced at the model's published input rate, so the total scales linearly and never moves backwards as traffic mixes change.

Where the price comes from

Prices come from LiteLLM's community-maintained pricing table, unless you've set a per-model override in — an override always wins.

Why a figure can show $0.00

Pricing tables go stale or simply don't list newer/unlisted models. When that happens the dollar estimate falls back to $0.00 even though real tokens were saved — check the token counts (directly measured, not priced) if a $ figure looks wrong, and add a pricing override in Settings for any model that's missing.

Estimated vs measured

Anything marked estimated depends on this pricing table and can drift. Token counts are measured directly from the tokenizer/API usage fields and don't depend on pricing at all.
